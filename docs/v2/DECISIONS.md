## D-010 — GMST는 v1.0.2 검증 번역 재사용
- 상태: 확정
- 날짜: 2026-09-29
- 결정: 메뉴 GMST 926개는 Gemini로 재번역하지 않는다.
- 결정: `GMST_REUSE_V1_926.csv`를 v2 빌드 입력으로 사용한다.
- 이유: 메뉴/시스템 문구는 v1.0.2에서 실제 게임 검증이 끝났으며 재번역 이득보다 회귀 위험이 크다.
- 예외: `sPlural`의 빈 한국어는 의도된 값이다.

## D-011 — 용어 증거 우선순위
- 상태: 확정
- 날짜: 2026-09-29
- 결정: 용어는 다음 순서로 판단한다.
  1. 사용자/프로젝트 확정
  2. 최신 Skyrim SST exact
  3. 최신 Skyrim BOOK/DESC 반복 문맥
  4. 현재 한국어 TES 커뮤니티/나무위키 표기
  5. Oblivion Remastered 반복 메모리
  6. v1은 QA/비교 참고
- 이유: Oblivion 전용 고유명사는 Skyrim exact에 없을 수 있으므로 BOOK과 현재 커뮤니티 용례까지 교차해야 한다.

## D-012 — SST 일반어는 exact-only, 핵심 고유명사만 phrase-context
- 상태: 확정
- 날짜: 2026-09-29
- 결정: SST 일반 용어는 원문 전체 정확 일치일 때만 강제한다.
- 결정: 직접 검증한 핵심 고유명사만 문장 내부 부분 일치를 허용한다.
- 결정: phrase-context는 대소문자를 구분한다.
- 이유: `Anvil→모루`, `Age→Mage` 같은 잘못된 부분일치를 차단한다.

## D-013 — Gemini 출력은 정수 순번으로 구조 검증
- 상태: 확정
- 날짜: 2026-09-29
- 결정: 모델에게 FormID/복합 ID를 재출력시키지 않는다.
- 결정: 각 항목에 정수 `n`을 부여하고 동일한 n을 반환하게 한다.
- 결정: 누락/중복/재정렬 시 요청 실패로 처리하며 저장하지 않는다.
- 이유: 긴 배치에서 ID 문자열 변형 및 배열 한 칸 밀림을 실제 파일럿에서 확인했기 때문이다.

## D-015 — Gemini quota는 project × model 별도 관리
- 상태: 확정
- 날짜: 2026-09-30
- 결정: 4개 API 키는 서로 다른 Google Cloud project로 취급한다.
- 결정: 3.5 Flash-Lite와 3.1 Flash-Lite의 일일 안전선도 모델별로 따로 계산한다.
- 결정: backfill은 3.5를 우선 사용하고 해당 project/model이 429 또는 안전선에 도달하면 3.1로 폴백할 수 있다.
- 이유: project 전체 합산 카운터는 실제 모델별 quota를 과도하게 제한한다.

## D-016 — QUST/CNAM은 플레이어 퀘스트 일지체
- 상태: 확정
- 날짜: 2026-09-30
- 결정: QUST/CNAM은 NPC 대사가 아니라 플레이어의 진행 기록/내적 독백으로 번역한다.
- 결정: `-했다/-해야 한다/-인 것 같다` 계열의 평서 일지체를 기본으로 한다.
- 결정: 원문 속 직접 인용이 아닌 이상 이유 없는 `-습니다/-해요/-세요`를 사용하지 않는다.

## D-017 — 문장형 DIAL/FULL은 플레이어 선택문 우선
- 상태: 확정
- 날짜: 2026-09-30
- 결정: 문장형 DIAL/FULL은 NPC 응답문이 아니라 플레이어가 보는 토픽/선택문으로 우선 취급한다.
- 결정: 원문 근거가 없는 고풍체/하게체/하오체를 만들지 않는다.
- 결정: 명사형 DIAL/FULL은 간결한 토픽/UI label로 처리한다.

## D-018 — 조사 선택형/PN 숫자 누출은 로컬에서 정규화
- 상태: 확정
- 날짜: 2026-09-30
- 결정: `(이)가`, `(을)를`, `으(로)`, `의(의)` 등 모델이 남긴 조사 선택형은 로컬 복원기로 정상 조사 하나로 확정한다.
- 결정: `__PN001__` 등의 token index가 한국어 고유명사 뒤 숫자로 누출되면 해당 확정 mapping에 근거해 제거한다.
- 결정: 숫자 제거 후 조사는 최종 한국어 이름의 받침 기준으로 다시 선택한다.

## D-019 — 영어식 소유격을 '의'로 기계 번역하지 않음
- 상태: 확정
- 날짜: 2026-09-30
- 결정: 영어 possessive/'s/of/noun-chain 때문에 `의`를 자동 사용하지 않는다.
- 결정: 한국어에서 명시적 속격이 자연스럽고 필요할 때만 `의`를 사용한다.
- 결정: `{GEN}` 잠금 marker도 같은 원칙을 따른다.
- 주의: 기존 번역의 `의`를 기계적으로 일괄 삭제하지 않고 문맥 QA 대상으로 본다.

## D-020 — BOOK은 책 전체 문맥과 book-local terminology memory 사용
- 상태: 확정
- 날짜: 2026-09-30
- 결정: 한 책에서 확인된 exact term은 동일 영어 구문이 다른 segment에 다시 나오면 그 segment에도 잠금을 전파한다.
- 결정: PN token 번호는 한 책 전체에서 유일하게 유지한다.
- 결정: glossary 검증은 실제 해당 segment에 mapping이 생성된 용어만 검사한다.
- 이유: segment별 token 재사용과 부분 glossary 적용 때문에 unresolved token/glossary miss가 발생한 실제 사례를 방지한다.

## D-021 — v1.0.2 비교는 최종 회귀 탐지용
- 상태: 확정
- 날짜: 2026-09-30
- 결정: 모든 backfill과 전역 QA 후 v1.0.2와 v2를 영어 원문 기준으로 전수 비교한다.
- 결정: v1은 source of truth가 아니며 자동 덮어쓰기하지 않는다.
- 용도: v1에는 정상인데 v2에서 의미가 빠지거나 문체/용어가 회귀한 구간 탐지 및 좋은 기존 표현 참고.
